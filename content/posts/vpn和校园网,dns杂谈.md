# 1:系统代理后的代理服务器

![zhai](images/2026-05-08/image6.png)
## 1. 为什么用 VPN 时它会自动变？
当你开启 VPN 软件（如 Clash、V2Ray 等）并选择“系统代理”模式时，软件会通过脚本强行修改 Windows 的这个注册表项。

原理： 它把地址设为 127.0.0.1（你自己的电脑），端口设为 7897（或其它）。

意义： 这其实是在给所有软件发信号：“喂！你们想上网的话，先把数据包发给坐在 7897 端口的代理软件，由它帮你们转发。”

## 2. 为什么不用 VPN 时必须手动关掉它？

因为这个“告示牌”没被及时撤掉。

当你退出 VPN 软件，如果它没有正常清理设置，Windows 依然认为上网要经过 7897 端口。

但此时你的代理软件已经关了，没有人在 7897 端口接收数据。

结果： 你的浏览器就像无头苍蝇，把请求发往一个没人的港口，导致国内、国外网站全部卡死，报错“无法连接到代理服务器”。

## 3. 为什么开着 VPN 时，国内网站又能打开了？

这是因为现代代理软件都有 “分流 (Rules)” 功能。

虽然流量都经过了代理软件，但软件内部有一张表：如果是百度、知乎等国内地址，它会选择“直连”；如果是 Google、OpenAI，它才走“代理节点”。

所以，只要代理软件开着，它就能帮你聪明地处理分流。



# 2. 宿舍网 vs. 校园网 vs. 流量
结论：并不完全一样，校方依然能看到你“出海”，但看不见你“干了什么”。

流量的效果： 流量是直接通过运营商（移动/电信/联通）基站出网，完全绕过了学校的内网监控。

宿舍网/校园网： 虽然你觉得它们是两个信号，但出口通常是统一的。无论你在宿舍还是教学楼，你的数据包最终都要经过学校的核心交换机和防火墙才能流向互联网。

监控深度： * 即便用了 VPN： 学校虽然看不见你具体的聊天记录或代码内容（因为加密了），但他们能通过流量特征分析（Traffic Analysis）知道你的 IP 正在与一个国外的中转服务器进行大规模数据传输。

安全建议： 在学校环境下，TUN 模式（虚拟网卡）+ 强加密协议是最安全的方案，因为它让你的所有流量看起来就像一堆乱码，比单纯的“系统代理”伪装得更深。

哪个安全？

结论： 在不挂 VPN 的情况下，都不安全。在挂了 VPN 且开启 TUN 模式 的情况下，两者一样安全。

分析： 宿舍网和校园网通常共用一个出口防火墙。学校的网络中心就像一个“大门岗”，无论你从宿舍（后门）还是教学楼（前门）出去，都要经过这个岗亭。

学校知道你翻墙吗？

真相： 学校知道你在“加密通话”，但不知道你在“聊什么”。

伪装深度： * 系统代理： 像是在信封外面贴了个条子说“这封信要去美国”，虽然内容加密了，但“寻址”动作太明显，容易被拦截。

TUN 模式 + 强加密： 像是把整封信塞进了一个完全漆黑、没有任何标记的保险箱，并直接通过专用的“地下隧道”运出去。

学校看到的： 防火墙只能看到你的 IP 正在向一个国外的 IP 发送大量乱码（加密数据流）。他们知道你在用代理工具，但因为数据是强加密的，他们无法解码，也无法确定你是在用 Cursor 写代码还是在看 YouTube。

安全建议： 在学校这种受管辖的网络环境下，TUN 模式 是必须的。它能防止 DNS 泄漏，确保你的寻址请求不被学校的 DNS 服务器记录。

# 3. 系统代理切换到 TUN 模式会发生什么？
结论：通常不会断网，但会产生“冗余”路径。

如果你先开了系统代理，然后又切换到 TUN 模式：

流量走向： 软件 -> 系统代理 (127.0.0.1:7897) -> 代理软件内核 -> TUN 虚拟网卡 -> 互联网。

现象： 你的网络依然是通的。因为 TUN 模式像是一个巨大的“兜底网”，它会捕获所有从网卡出去的流量。即便流量已经被系统代理转发了一次，最终还是会被 TUN 模式抓住发往国外。

风险： 这样配置性能略有损耗，且如果 VPN 软件崩溃，系统代理那个“告示牌”没撤掉，你就会遭遇断网。

# 4. 系统代理模式下，关掉“图2”的勾会怎样？
结论：如果你只开启了系统代理模式（没开 TUN），关掉这个勾，你几乎百分之百打不开国外网站。

![zhai](images/2026-05-08/image7.png)

为什么会这样？
因为系统代理模式是靠“自觉”的。浏览器、Cursor 这些软件启动时会先看一眼 Windows 的系统设置。

如果有勾，它们就走代理。

如果没有勾，它们就直连。

例外情况（为什么你之前可能觉得没区别）：
如果你同时开启了 TUN 模式，那么即便你手动关掉了“图2”的勾，你依然能上国外网。

原理： 虽然软件尝试“直连”，但流量在流出网卡的瞬间，会被 TUN 模式这个“地网”给兜住，强行拽进代理隧道。

最终总结
为了不被学校轻易拦截： 请坚持使用 TUN 模式。

# 5.学校到底知不知道你在“翻墙”？

真相是：学校知道你正在使用“某种加密隧道”，但很难实锤你在“翻墙”。

流量特征： 当你开启 TUN 模式，所有流量被封装成加密协议。学校的防火墙（如深信服、华为等）会看到你的 IP 正在持续向一个特定的国外服务器发送大量的加密 UDP 或 TCP 数据包。

识别风险： 这种行为模式和“翻墙”高度吻合。但是，由于数据是强加密的，学校看不见具体的域名（如 openai.com）或内容。在他们看来，这也可能是你在连接某个实验室的私有 VPN 或进行加密的数据备份。

安全对比：

系统代理： 容易因为 DNS 泄露导致学校看到你尝试解析 google.com 的记录，相当于“自首”。

TUN 模式： 所有的解析和访问都锁在“保险箱”里，是目前在校园网环境下的最高安全等级。

# 6.开发者的终极选择：系统代理 vs. TUN？
针对你目前“看文档 + Cursor 写代码”的需求，我给出的标准配置方案如下：

核心建议：固定使用 TUN 模式
理由： 许多开发工具（比如 Git 命令行、Python 的 pip、Cursor 的某些底层进程）根本不看系统代理设置。只有 TUN 模式这种底层接管，才能保证你写代码时不会莫名其妙地报错。

DNS 必须改吗？

必须改。 即使开了 TUN，手动设置 8.8.8.8 或 1.1.1.1 也是为了强制触发 VPN 拦截。

这就像给包裹贴上一张“发往海外”的显眼标签，确保它能被 VPN 这个“海关人员”准确拦截并扔进加密通道，而不是被电脑偷偷塞进本地的“平邮信箱”（运营商 DNS）。

# 7.不用 VPN 时，该如何还原？
当你离开宿舍或者准备关掉 VPN 休息时，为了保证网络正常，你需要做两件事：

第一步：还原 DNS 为“自动”
这是最重要的。如果你不改回自动：

你的电脑会尝试直连 8.8.8.8。

由于没有 VPN 的隧道保护，这个请求大概率会被校园网拦截或因网络环境问题超时。

后果： 你的网页会打不开，或者加载极其缓慢，仿佛断网了一样。

第二步：清理系统代理“残余”
如果你之前不小心点到了“系统代理”模式，记得检查一下图 2（局域网设置）里的那个勾是否已经去掉。

检查方法： 确保那个 “为 LAN 使用代理服务器” 是取消勾选的状态。

开发者进阶建议：
如果你觉得手动改 DNS 烦，可以在 Windows 的网络设置里，把 DNS 设为 114.114.114.114（国内常用）。

优点： 即使关了 VPN 也能用，开了 VPN 后配合 TUN 模式的“DNS 劫持”，它也会被安全转发。但这属于折中方案，对于 Cursor 这种风控极严的软件，手动 8.8.8.8 + TUN 依然是最稳的“防爆”组合。

## tips:
### 1. 为什么系统代理容易 DNS 泄露？
系统代理（System Proxy） 像是一个软件层面的“告示牌”。

工作机制： 它告诉支持它的软件（比如浏览器）：“嘿，如果你想访问网页，请把数据包发到我的端口（比如 7897）。”

泄露点： 很多软件在“寄信”（发数据）之前，需要先“查地址”（DNS 解析）。由于系统代理主要管的是“数据传输”，有些软件会跳过代理，直接向 Windows 系统询问地址。

结果： 系统会默认找运营商（校园网）的 DNS 服务器问路。这时，校园网后台就会看到你的 IP 正在查询 cursor.com。虽然你还没开始传输数据，但你的意图已经暴露了。这就是所谓的 DNS 泄露。

### 2. TUN 模式：既然不设置代理服务器，它是怎么工作的？
这是最神奇的地方。TUN 模式不靠“告示牌”，它靠的是“物理拦截”（在内核层伪造一个网卡）。

它的工作流程如下：
创建虚拟网卡： 当你开启 TUN 模式，VPN 软件会在你的 Windows 里安装一个叫“Meta”或“Clash”的虚拟网卡。

接管路由表： 软件会修改系统的路由表（类似于交通指挥中心），把“默认网关”指向这张虚拟网卡。

流量捕获： 现在，你电脑里产生的任何流量（不管是浏览器看视频、Cursor 写代码、还是后台偷偷联网的程序），只要它们想出网，数据包都会被强制导向这张虚拟网卡。

保险箱封装： VPN 软件像一个守在虚拟网卡出口的邮差。它把所有进入网卡的原始数据包（包括 DNS 请求）抓起来，塞进一个高强度的加密隧道里，然后再发往海外节点。

### 3. 为什么 TUN 模式是“保险箱”？
强制拦截： 因为它是在网络层（OSI 第三层）工作的，软件根本不知道自己被代理了。哪怕软件想“偷跑”去直连国内 DNS，也会因为路由表的限制，被强行拽回虚拟网卡里。

DNS 劫持： 代理软件会拦截所有去往 53 端口（DNS 端口）的流量。即便你手动设了 8.8.8.8，数据包在出网卡前就被代理软件掉包了，它会代你向海外节点发起解析。

对校园网隐形： 校园网防火墙只能看到你的电脑在发送一堆完全加密的 UDP 数据。它看不出里面哪些是 DNS 请求，哪些是代码数据，更不知道你访问了哪些域名。

4. 离线后的“还原”操作：一键复原指南
既然你用的是大学生宿舍网，最怕的就是关了 VPN 却上不了网（甚至进不去校园网认证页）。不用 VPN 时，请务必执行以下“三连操作”：

关闭 TUN 开关： 这样系统会自动把“默认网关”换回你的真实 Wi-Fi 网卡。

还原 DNS 为“自动获取”： * 在之前的 WLAN 属性里，把手动改的 8.8.8.8 换回 “自动获得 DNS 服务器地址”。

理由： 只有这样，你才能在不翻墙时顺利访问校园网的内网资源、认证页面，以及国内那些对 DNS 延迟要求极高的网页。

（可选）清理缓存： * 打开 Cmd，运行 ipconfig /flushdns。这能确保你的电脑不会因为记住了旧的“海外地址”而导致国内网访问异常。

总结一句话：
TUN 模式是靠“修改地图（路由）”来强制接管全线流量的；而系统代理是靠“摆告示牌”来引导部分流量的。作为 CS 专业学生，做开发时死守 TUN 模式 + 8.8.8.8，平时生活时关掉 TUN + 自动 DNS 是最高效、最专业的方案。
